## Instructions for AI agents working in this repo

1. **Consult [`codebase-analysis-docs/CODEBASE_KNOWLEDGE.md`](codebase-analysis-docs/CODEBASE_KNOWLEDGE.md) before a large or cross-cutting change.** It documents the load-bearing patterns (transactional outbox, reconciliation-never-creates-a-charge, idempotency-by-DB-constraint) that most financial-code bugs in this repo's history have come from violating.
2. **Follow [`docs/CODING_CONVENTIONS.md`](docs/CODING_CONVENTIONS.md)** — naming, the no-service-layer architecture, and the transactional-outbox pattern for any change touching a `Payment`/`InvoicePayment`/`RefundRequest`.
3. **Follow the architectural principles in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)** — especially: external HTTP never inside a DB transaction; webhook business logic lives in `processFinixWebhookEvent`, not the ingress `POST` handler; reconciliation code may repair state but must never call a charge/reversal-creating Finix endpoint.
4. **Prefer existing patterns over introducing new ones.** If you need "schedule some follow-up work," use the existing `BackgroundJob` outbox (`src/lib/jobs/`) — do not introduce a new queue mechanism. If you need "repair a financial gap," extend the existing reconciliation modules (`src/lib/reconciliation/`) rather than writing a new one-off repair path.
5. **The governing rule for anything touching money**: *WGC is allowed to become slower under load. It is never allowed to become financially incorrect.* When in doubt between a faster implementation and a more-obviously-correct one for a financial write path, choose correctness.
6. **Never trust a client-supplied `churchId`** for anything security- or tenant-isolation-relevant — always resolve it from `requireMerchantSession()` (see [`docs/AUTHENTICATION.md`](docs/AUTHENTICATION.md)).
7. **Docs and code can drift** — this documentation set was generated by reading the codebase once; if you find a doc that contradicts the actual code, trust the code and flag/fix the doc (see [`codebase-analysis-docs/CODEBASE_KNOWLEDGE.md`](codebase-analysis-docs/CODEBASE_KNOWLEDGE.md)'s own "Documentation TODO" section for known gaps).
